# ContentGuard｜项目总结

## 项目简介
基于 Python、FastAPI 构建的模拟内容审核服务，围绕内容分类、审核任务创建、任务查询和人工审核流程，实践接口自动化、数据驱动测试、Diff 测试及性能测试。

## 技术栈
Python、FastAPI、Pydantic、pytest、TestClient、Locust、Git、GitHub Actions。

## 核心功能
- 内容分类：根据关键词返回 `pass`、`review` 或 `block`。
- 任务管理：创建审核任务、按 task_id 查询任务。
- 人工审核：处理 pending 任务，限制 completed 任务重复审核。
- 版本对比：通过 V1/V2 逻辑及 Diff 用例检查规则变化。

## 测试实践
1. 使用 pytest 和 FastAPI TestClient 编写接口及业务逻辑测试。
2. 使用 JSON 数据组织参数化测试，覆盖正常、异常、边界和优先级场景。
3. 验证任务创建、查询、人工审核及状态流转。
4. 使用 Diff 测试比较不同版本的审核结果。
5. 使用 Locust 对创建、查询、人工审核、最终查询组成的完整链路压测。
6. 通过独立微基准脚本比较字符串匹配、正则和 Aho-Corasick 等方案。

## 性能测试结果
本机环境下，50 用户、5 users/s、持续 3 分钟的完整业务链路压测两次：

| 指标 | 第一次 | 第二次 |
|---|---:|---:|
| HTTP 请求数 | 17,504 | 17,607 |
| 失败数 | 0 | 0 |
| 平均响应时间 | 1.22 ms | 1.21 ms |
| P95 | 2 ms | 2 ms |
| P99 | 3 ms | 3 ms |
| 整轮平均 RPS | 97.24 | 97.82 |

以上仅代表特定本机环境和模拟业务场景，不代表生产环境容量或线上 SLA。四个 HTTP 请求构成一次业务流程，HTTP RPS 不等于完整业务流程每秒完成数。

## 项目结论
项目实践了从业务规则拆分、接口自动化、异常与状态测试、版本差异验证，到多接口链路压测和性能分析的过程。关键词实验显示算法选择应结合规模和目标：当前 V1 仅有少量关键词，保留 Python `in` 判断更简单，且独立微基准实测快于预编译正则。

## 当前限制与后续方向
- 任务数据保存在进程内存字典中，服务重启后会丢失。
- 审核规则为模拟规则，不代表真实内容安全策略或 AI 模型能力。
- 性能数据来自本机环境，不能直接外推生产环境。
- 后续可考虑接入数据库、完善 CI 执行记录，并增加真实 AI 审核模型及其准确性、鲁棒性测试。
